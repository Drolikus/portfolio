ERP: a dashboard that stays readable

A planned internal operations dashboard. The goal is to keep dense data — tables, filters, and status flows — calm and scannable instead of cramped. This page describes the intent before the build begins.

Problem

Density without clutter

Operations tools drown in data. The challenge is rhythm: spacing, alignment, and hierarchy that let a busy table still read at a glance.

Plan

Tables, filters, and states first

Start with the data table and its states — empty, loading, error, filtered — then layer filtering, sorting, and status flows on top.

Scope

One honest first version

A focused v1: a list view, detail panel, and a couple of real status workflows — shipped before adding breadth.

Planned build pass

  • Design the table component with all data states.
  • Add filtering, sorting, and pagination.
  • Build a detail panel and status transitions.
  • Stress test dense layouts on small screens.
